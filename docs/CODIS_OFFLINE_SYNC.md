# CODIS 3.12.0 — العمل دون إنترنت + المزامنة + قفل المخزون + معاينة حادة

## 1) كيف صار التخزين والمزامنة (Offline-First)
| الطبقة | الدور |
|---|---|
| `localStorage` (`life_organizer_data_v1`) | مسار الحفظ المتزامن السريع `saveData()` — نسخة عمل مؤقتة، **ليست** مصدر الحقيقة |
| **IndexedDB** `codis-local` (`CodisLocalDB`) | مرآة دائمة لنسخة العمل `work` (مرتبطة بمعرّف المالك) + لقطة **الأساس** `base|<uid>` = آخر نسخة أكّد الخادم أنها عنده |
| الحساب (Supabase `progress`) | **مصدر الحقيقة النهائي**. `save_progress(p_data, p_base_version)` رفع تفاؤلي (CAS) بإصدار الخادم |

- **لا سجل عمليات منفصل:** بدلاً منه «نسخة العمل + الأساس + علامة dirty». المقارنة الثلاثية (أساس/جهاز/حساب) تعطي أثر إعادة تشغيل العمليات دون سجل ثانٍ، والمعاملات المالية لها معرّفات `(type + referenceId)` تمنع التكرار.
- **حفظ قبل الإبلاغ:** `saveData()` يكتب محلياً أولاً؛ حالة «بالحساب» لا تظهر إلا بعد `save_progress` ناجح.
- **استعادة:** إن اختفت نسخة localStorage (إخلاء المتصفح) تُستعاد نسخة IndexedDB لنفس المالك فقط، مرة واحدة.
- **مشغّلات المزامنة:** عند الحفظ (تأخير 2.5ث) · `online` · `focus` · `pageshow` · `visibilitychange` · الإقلاع/الدخول · رسالة Background Sync من الـSW · إعادة محاولة بتدرّج (5ث ← 120ث). `navigator.onLine` لا يُعتمد عليه: الدليل هو نجاح الطلب الفعلي.
- **الحالات الظاهرة (نص مستقل لكل واحدة):** متزامن مع الحساب · جارٍ رفع التغييرات · محفوظة على الجهاز بانتظار الرفع · دون اتصال (محفوظة على الجهاز) · تعذّر الوصول للخادم (ستُعاد المحاولة) · انتهت جلسة الدخول (التغييرات محفوظة).

## 2) الدمج بدل «اختر نسخة»
أُزيلت كل نوافذ الاختيار (`askChoice` / `resolveConflict` القديم / اختيار ضيف-حساب). `CodisMerge.merge(base, local, remote)`:
- كائنات: مفتاحاً مفتاحاً · مصفوفات ذات `id/uid/ev`: اتحاد بالمعرّف ودمج كل عنصر · غيرها: اتحاد بالقيمة.
- **الحذف** يُنفَّذ فقط إن لم يعدّل الطرف الآخر العنصر (التعديل يتفوّق على الحذف — لا يضيع شيء بصمت).
- حالات أحادية الاتجاه: `owned < used < sold`، `running < cancelled < done`، `pending < resolved` (الأعلى يفوز).
- **المحفظة (كوين/فضة):** الرصيد = رصيد الحساب + مجموع معاملات هذا الجهاز **الجديدة** فقط؛ معاملة `(type + referenceId)` المكررة تُحسب مرة واحدة (بيع/شراء/تحويل مكافأة لا يتكرر).
- **بعد الدمج:** اتساق المخزون مع دفتر المحفظة (نسخة لها معاملة بيع ← `sold`)، وقرار «أخذ المكافأة» على جهاز و«كوين» على آخر ← مكافأة واحدة فقط.
- تعارض قيمة مفردة حقيقي (حقل معدَّل من الطرفين) ← الأحدث زمنياً (وقت آخر تغيير للجهاز مقابل `updated_at`)، بقرار حتمي.
- **ضيف → حساب:** دمج تلقائي بلا أساس (اتحاد) مع نسخة احتياطية محلية تبقى (آخر نسختين).
- **حساب آخر على الجهاز:** تغييراته المعلقة تُركن باسم صاحبها (`codis_acct_<uid>`) ولا يعتمدها حساب آخر، وتُدمج تلقائياً عند عودته. **تسجيل الخروج** بتغييرات معلقة: تُركن باسم المالك (بلا نافذة) ثم تُدمج عند الدخول.
- بعد الدمج الناجح يُرفع الناتج بالإصدار الجديد؛ سباق جديد ← يُعاد الدمج (حتى 6 مرات). تعديل المستخدم أثناء الدمج يُدمج فوق النتيجة (لا يضيع). تُعاد تحميل الصفحة مرة واحدة فقط إن اختلفت النتيجة عمّا بالجهاز.

## 3) المخزون والمؤقتات
- «استخدام» الزر الرئيسي، «بيع» ثانوي؛ المكافأة ذات المدة: «ابدأ · المدة».
- القفل في `CodisEconomy.sellCheck` (كل مسارات البيع الفردي/الجماعي/المكررات/استدعاء مباشر) عبر `codisTimerBlocksSell`: مؤقت شغّال **أو** منتهٍ لم يُثبَّت تحوّله إلى «مستخدمة» بعد.
- تثبيت الانتهاء idempotent: حقل `fin` بالمؤقت؛ فشل `markUsed` ← إعادة محاولة كل 4ث/عند العودة حتى ينجح، والبيع محجوب طوال ذلك. النسخة المستخدمة/المباعة سلفاً تُعد مكتملة.
- **استثناء المطوّر** (`CodisLimits.bypass('timer.sellActive')`) باقٍ حسب القاعدة الدائمة للمشروع (حساب المطوّر الموثَّق بلا قيود)؛ المستخدم العادي لا يملك أي طريق للتجاوز.

## 4) معاينة البطاقة (CodisCardPeek)
**السبب الحقيقي:** كانت البطاقة تُرسَم بحجمها الصغير ثم تُكبَّر بـ`transform: scale` مع `will-change: transform` و`drop-shadow` على الطبقة نفسها ⇒ تُمدَّد صورة الطبقة المرسومة سلفاً بدل إعادة التصيير ⇒ بكسلة/بهتان.
**الحل:** تُرسَم البطاقة فعلياً بحجمها النهائي (`zoom:k` داخل غلاف `peek-fly`) والـFLIP يبدأ من `scale(1/k)` إلى 1 (تصغير ثم عودة، لا تكبير صورة صغيرة). أُزيل `will-change`. متصفح بلا `zoom` ← المسار القديم بلا `will-change`.

## 5) الإشعارات (Web Push)
الموجود والمفحوص: `CodisPush` (اشتراك + جدولة/إلغاء) · `sql/codis_push.sql` (جداول + RPC بـRLS + `push_claim_due` مرة واحدة لكل حدث) · `supabase/functions/codis-push` (VAPID، تنظيف 404/410، TTL) · `sw.js` (`push` + `notificationclick`).
**المضاف:** `CodisPush.status()` برسائل دقيقة (غير مدعوم / iOS يحتاج تثبيتاً / تسجيل دخول / **VAPID فارغ** / إذن مرفوض) بدل نص نجاح مضلِّل · إعادة جدولة المؤقتات التي لم تصل للخادم أثناء الانقطاع بعد كل مزامنة ناجحة · `sw.js` v4: `sync` و`pushsubscriptionchange`.
**مطلوب منك (خارج المشروع):** مفتاح VAPID العام في `<meta name="codis-vapid-public-key">` + أسرار الدالة + نشرها + `pg_cron` (راجع docs/CODIS_PUSH_SETUP.md). **الميتا فارغة حالياً ← إشعار الخلفية لن يصل حتى يُضبط.**

## 6) حدود صريحة
- لم يُختبر: Supabase الحقيقي (RLS/الجلسات)، تسليم Web Push الحقيقي لجهاز مغلق، تثبيت PWA على iOS، فتح الحساب على جهازين فعليين. الاختبار استعمل خادماً **وهمياً داخل الصفحة** يحاكي `progress` و`save_progress` (إصدارات + تعارضات + انقطاع).
- الخادم يخزن لقطة كاملة (الدمج عند العميل). قفل بيع المؤقت **في العميل** لا في الخادم (الخادم لا يرى عمليات منفصلة).
- جهازان أنفقا الكوين نفسه دون اتصال ← الدمج يحتفظ بالعمليتين (لا فقد) وقد يصير الرصيد سالباً مؤقتاً (يمنع الإنفاق حتى يعود موجباً).
- Background Sync يوقظ صفحة مفتوحة/معلّقة فقط؛ الـSW لا يحمل جلسة الحساب فلا يرفع والتطبيق مغلق تماماً — الرفع عند فتحه/عودته.
- `tests/push_sql_test.mjs` (PGlite) لم يُشغَّل هذه الجولة (يحتاج `npm i @electric-sql/pglite`)؛ ملفات SQL لم تتغير.
